## Notable decisions
1. **Consume workspace packages from compiled `dist/`.** Alternatives named: TS source exports; custom export condition. Reason given: plain-Node API cannot load `.ts` from a dependency without a bundler. Cost named: `lint`, `typecheck` and `test` run `build:packages` first. Held up in CI and tests; reviewer flagged the coupling as non-blocking and the coordinator accepted it. Future cost is plausible but unproven.
2. **Plain `tsc`, no Turborepo/Nx/tsup.** Reason: fewer tools for a scaffold. Held up so far; revisit if build time grows (reviewer's note).
3. **Type-aware zero-`any`** (`no-explicit-any` + five `no-unsafe-*`), proven by tests. Reason: `no-explicit-any` alone misses leaks like `JSON.parse`. Held up (reviewer re-proved it). Scope is `packages/*/src` only; apps are not covered, consistent with doc 11's wording, but this is a limit worth noting for later tasks that put logic in apps.
4. **TypeScript 6.0.3 over 7.0.x.** Reason: typescript-eslint 8 supports `<6.1` only. Lockfile consistent. Reviewer noted the very-recent-major risk.
5. **Single root `eslint .`** instead of per-workspace lint. Held up.
6. **Extras** (app-import rule, engine-strict, etc.): chose to include them rather than ask first; coordinator and reviewer later accepted them. The app-import rule traces to doc 05 §2, so the extra has a spec basis.
7. **Open questions to coordinator after building** (push branch, SHA pins, coupling, engine-strict) instead of deciding unilaterally on the policy-ish ones.
